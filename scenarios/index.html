Scenarios
Where the technology fails on purpose

Short missions built around the mistakes that actually happen. Each one puts you in front of a real decision, lets you make it, and then shows you what it cost. Nothing here is live and nothing can break.

Progress is stored in this browser only — never uploaded.
▶ How to write a new scenario

A scenario is one JSON file. You never edit the engine, the page, or any CSS — you add a file to scenarios/data/ and add its id to scenarios/data/index.json. That is the whole process.

1. Add the file

Create scenarios/data/my-scenario.json:

{
  "id": "my-scenario",
  "title": "The one where it goes wrong",
  "subtitle": "A line that says what they will practise",
  "audience": "Staff",
  "minutes": 10,
  "summary": "Shown on the card in the library.",
  "takeaway": "The sentence you want them repeating afterwards.",
  "steps": [ ... ]
}

2. Register it

Open scenarios/data/index.json and add the id to the list:

{ "scenarios": ["redaction-trap", "citation-check", "my-scenario"] }

Order in that list is the order on the page. That is the only thing that file controls.

Step types

TypeWhat it does
briefSets the scene. Text, an optional artifact, and a Continue button.
choiceOne right answer. Every option carries its own feedback.
multiSelect all that apply. Scored as all-or-nothing.
sortPut each item in a bucket. This is the Sort the Stack format.
inspectFind the problems hidden in a document. Decoys allowed.
terminalType commands against a simulated shell.
revealThey take an action, then see the consequence.

Artifacts

Any step can carry an artifact — the thing they are looking at:

KindFields
emailfrom, to, date, subject, body
doclines[] — a string, or {heading}, or {redacted:true, under:"…"}
chataiName, turns[{who:"ai"|"you", text}]
tablecolumns[], rows[][]
terminallines[]

Worked example — a choice step

{
  "type": "choice",
  "title": "The request",
  "body": "It is 4:45 on a Friday.",
  "artifact": {
    "kind": "email",
    "from": "dean@example.edu",
    "subject": "Need this tonight",
    "body": "Can you send me the list of students who failed?"
  },
  "prompt": "What do you do first?",
  "options": [
    { "text": "Send it — the dean asked.",
      "correct": false,
      "feedback": "Authority is not the same as authorisation." },
    { "text": "Check whether the dean has an educational interest in those records.",
      "correct": true,
      "feedback": "That is the FERPA question, and it survives being asked on a Friday." }
  ]
}

Marking up an inspect step

Write the passage in text and wrap each clickable region in {{id|the words they click}}. Then describe each id in spans. Set "target": true for real problems and leave it off for decoys — decoys are what make it a skill rather than a scavenger hunt.

{
  "type": "inspect",
  "prompt": "Three things here should stop you. Find them.",
  "text": "Per our call, {{a|attached is the full unredacted file}} …",
  "spans": [
    { "id": "a", "target": true, "label": "Unredacted file",
      "note": "Nothing about the request required the whole file." }
  ]
}

Things worth knowing

  • Options are shuffled so the right answer is not always in the same place. Set "shuffle": false on a choice step when order matters.
  • Text formatting supports **bold**, *italic*, `code` and blank lines for paragraphs. Everything else is escaped, so a scenario file can never break the page.
  • Deep links work. #my-scenario opens it and #my-scenario/4 opens at step 4 — useful with the QR button when you want thirty people on the same screen at once.
  • Progress is local. It lives in this browser and is never uploaded.
